How It Works
The charts read the rows. Each row applies from its From date to its To date, or with no To, until the next row. A day no row covers is left blank. Apply Invoices To Rows adds a row for every change in the imported invoices (each line's charge spread evenly over its own days, PPC left out) and replaces any adjustment email rows for the days the invoices cover; an email row that runs on past the last invoice is kept from the day after it. Email rows are estimates. Invoices import straight away; rows and PPC rows save with Save.
Read Email reads two kinds of email. An order change ("The changes we discussed", with a go-live date) adds a row from the go-live date, with products the email does not list copied from the email's current figures. Those current figures are only a check against the row before. A tactical change (a Tactical Adverts line with Current and Future slots) adds a row with the Future slots, from the Sent date for a reduction or the day after it for an increase; paste it with its Sent line. Flex is free: Flex Slots = Base Slots x Flex %, rounded to a whole slot. A month's cost is spread over the days in that month.
Slot increases (including tactical) start straight away; add a row from the first full day, which Add Row uses by default. Decreases take 30 days: use the go-live date in the email. On estimate rows, Tactical (£) works itself out as Tactical Slots x Market Extension / Base Slots (a tactical slot costs the same as a contracted slot); type over it if the email says otherwise. Tactical slots cannot be more than 10% of the base slots: Save refuses an estimate row over that.
In the charts, the current month and week add up only the days so far, up to today. Autotrader API allowance today: -.
In Edit Chart these are under Autotrader Costs. Costs (Sum): "at_cost_total", or each product on its own. Cost per slot per day for a week or month: Metric "at_cost_total", Sum, Divided By "at_total_allowance". PPC cost per click for each date: Metric "at_cost_per_ppc_click" (each invoiced month's PPC cost / its clicks; Apply Invoices fills the PPC Cost rows). PPC cost: Metric "at_advert_views_ppc", Multiplied By "at_cost_per_ppc_click", Sum.

Add Data Source
Optional. Every number column of a one-row-per-record table is already offered in Edit Chart as Sum Of and Average Of that column, along with Count Of Rows (an Average over a week or month is the average over every row, not of the daily averages). Add a metric here when it needs filters or two columns. Count Rows counts the rows that pass its filters, e.g. a filter of SUPPLIER_ID equals Z001 gives that supplier's deliveries per day. Average Of A Column averages a number column; Average Of A Difference averages one column minus another (two dates or times give days or minutes, later column first). Rows with a blank are left out. Averages show in Edit Chart as <name> - Average. Leave Count Rows By on (none) unless you want a count per value of a column like a status.
Adds a COMPUTE_ or PRODUCT_ table from PROD_CARSUPERMARKET_DB. Its metrics then show in Edit Chart under the name given here. One Row Per Date: each number column is a metric. One Row Per Date Per Name: each name in the Name Column is a metric (e.g. every event in COMPUTE_UX_TRACKING.GA4_DAILY_EVENTS), and a date the table has but a name has no row for counts as 0.
